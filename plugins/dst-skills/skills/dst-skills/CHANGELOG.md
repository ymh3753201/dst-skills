# Changelog

## 9.0.0 - Unreleased

- 保留原有 Codex `imagegen` 生成/编辑渠道及 Image 2 尺寸、记录和验收规则；新增可选 Ark CLI `+gen` 渠道，固定使用完整模型 ID `doubao-seedream-5-0-pro-260628`。
- 新增 `generation_channel`：默认 `codex_image_with_arkcli_fallback`，始终先调用 Codex；只有工具不可用、请求失败或无图输出时才降级到 Ark。用户仍可明确选择仅 Codex 或直接 Ark。
- 生图前强制执行认证状态、当前图片资源和模型 `supported_params` 三步核对；Agent 命令按 Ark CLI 共享协议记录调用来源，不在项目中保存 API Key。
- 尺寸和生成记录按渠道分开验证：默认降级策略必须同时通过 Image 2 和 Seedream 尺寸合同；Ark 降级记录必须包含脱敏的 Codex 失败证据。
- Seedream 5.0 Pro 每次只生成单图，完整套图逐页调用；拒绝组图、联网工具和 `guidance_scale` 等该模型不支持的参数，参考图最多 10 张。
- 正式命令显式传 `--watermark=false`；修复省略该参数时服务端默认添加“AI生成”水印的问题。
- Ark 渠道生成记录强制保存 `tool=arkcli.+gen`、完整 Pro 模型 ID、实际 `resource_id`、Ark CLI 版本、`watermark=false` 和成功状态；Codex 渠道继续保存原有工具、模型与请求 ID。
- 旧版 v8.2 项目仍只接受 Codex 图像生成记录；新增 Ark 记录规则仅适用于 v9，防止旧项目绕过原有渠道约束。
- 对格式错误的生图渠道和降级失败记录返回明确校验错误，避免校验器直接异常退出。
- 更新 Skill、插件元数据、模板、示例、评测和回归测试，并以 Ark CLI 真实生成烟雾测试验证文件落地与像素尺寸。

## 8.2.0 - 2026-07-18

- 修复“参数不足就少写文案”的执行缺陷：把事实文案与安全商业文案分开，缺少参数时仍必须用可见设计、审美利益、场景叙事、类目教育和买家引导形成完整商业表达。
- 非无字搜索首图必须具备标题、副标题和至少两条辅助信息；验证器会拒绝“商品静物＋两行大字”、空泛口号和伪详情场景页。
- 验证器新增页面数量一致性、占位文案和跨页重复文案检查，防止 placement 声明数量与实际页面不一致，或用同一句辅助文案批量填页。
- 每页 `visual_brief` 升级为可执行版式蓝图，明确商品占比、视觉焦点、文案区、信息层级、光线、景深、信息密度和内容模块。
- 版式蓝图新增商品数量/重复视图规则，防止开合对照、多角度和步骤页被模型误生成为多件商品；同时限制纯风险清单页，保持正向商业表达占主导。
- 新增六段式提示词编译器 `compile_prompts.py`，把商品身份、版式蓝图、逐字文案、美术执行和负面约束完整传给 Image 2，避免方案专业但生图提示词缩水。
- 把缺口分为 `project`、`claim` 和 `acceptance` 三种阻断范围；只有项目级问题停止整套方案，参数级缺口改用 `evidence_safe` 表达，不再让页面空洞。
- 确认门槛增加 `plan_sha256`、执行清单哈希、生成时间和提示词哈希，拒绝事后补写确认或确认后偷偷改变页面。
- 复核增加文案完整度、买家价值、提示词忠实度和事实安全检查；逐页五项评分任一低于 4 分必须返工，空泛的自填 `pass` 无效。
- 京东耳机失败案例冻结为不可变回归样本，测试不再依赖会被后续运行覆盖的 `generated/` 目录。

## 8.1.0 - 2026-07-15

- 修复“缺失信息被标成 `out_of_scope` 后绕过确认门槛”的问题：只有用户明确排除，或有证据证明某交付面确实不需要时，才允许超出范围。
- 把商品事实分为已验证、来源声称、口径歧义和缺失；每条事实必须写清适用范围与是否可用于文案，歧义数字不得直接进入成图。
- 把佩戴方式、参数归属、续航口径、功能和适配等归为商品事实，禁止用“AI 推断/AI 渲染”替代真实证据。
- 完整套图必须覆盖商品识别、使用/适配、证据、规格选择、风险/信任五个核心决策维度；任何未解决阻断项都会保持 `draft`。
- 每页新增主要决策和独特证据；确认态完整套图中，同一主要决策最多两页，避免用重复细节页、续航页和氛围页填数量。
- `plan.md` 成为必须真实存在的用户可读详细方案，`project.json` 只承担结构校验和执行记录，不能替代方案展示。
- 增加京东开放式耳机回归测试，覆盖 300mAh、45 小时、140 小时、佩戴方式和重复页面等确认门槛。

## 8.0.0 - 2026-07-15

- 把 Codex 身份明确为电商视觉策略总监、商业摄影指导和商品身份审核者；方案前强制完成素材角色、可见证据、原图缺陷、商品身份锁定与设计机会分析。
- 用 `decision_map` 建立买家决策地图；完整套图至少五个问题、三个高优先级问题。关键缺口保持 `draft`，不能用重复场景页掩盖，也不能进入方案确认。
- 移除“一个平台对应一种比例策略”的核心建模，改为多个真实 `placement`；每个落点分别记录名称、surface、数量、比例、选定像素、依据和研究引用。
- 完整平台套图默认至少两个 placement 和两种实际选定尺寸；单一图库等明确单落点任务仍允许统一规格。
- 在项目合同中加入 GPT Image 2 尺寸门槛，确认前拒绝边长不是 16 倍数、超出边长/宽高比/总像素范围的请求。
- 增加定位、目标买家、购买动机、购买阻力、创意总纲、信息层级和版式语法，防止“风格词 + 八个页面标签”冒充专业视觉方案。
- `--schema-only` 改为不依赖 Pillow；完整图片尺寸验证仍按 requirements 安装 Pillow 后运行。

## 7.2.0 - 2026-07-15

- 用真实淘宝家具回归案例修复“完整套图被设计成 8 张方图”：多交付面完整套图默认使用 `mixed_by_surface`，只有覆盖全部交付面的明确证据才允许统一比例例外。
- 指定平台的完整套图必须在确认前记录平台官方、店铺主题或用户后台证据；公开资料无精确像素时不再编造“平台标准”。
- 每页新增 `composition_type`，防止用多张重复场景图冒充详情内容；详情交付面至少包含一张信息型构图。
- 方案在展示给用户确认前必须通过结构预检，并逐页展示交付面、精确像素、比例、尺寸依据和页面任务。
- Contact Sheet 复核必须对商业信息覆盖、交付面差异、构图多样性、文字融合和商品一致性分别给出可见证据。

## 7.1.0 - 2026-07-15

- 修复“完整套图被示例收敛成 8 张统一 1:1”的问题：每页新增 `surface`，方案必须区分搜索主图、图库、SKU、详情页和活动图。
- 新增 `ratio_strategy` 与 `ratio_basis`，记录比例是按交付面混合、平台统一要求，还是单一交付面；不再允许无依据套用统一方图。
- 完整套图必须同时包含搜索主图和详情页；选择混合比例策略时，验证器要求至少两种实际宽高比。
- 更新项目模板、Shopify 示例和跨平台评测，使示例本身不再暗示“八张方图”。
- 发布检查新增同名 Skill 冲突与包体卫生门槛，避免旧快照被 Codex 当成另一份生产 Skill。

## 7.0.0 - 2026-07-15

- 将 Skill 重构为“创意优先”的轻量导演：多模态分析 → 动态方案 → 一次确认 → 模型原生完整成图 → 视觉返工。
- 最终消费者图片只允许由 Codex 图像生成或图像编辑能力完成；移除叠字器、布局合成器和旧版迁移器。
- 以一个精简 `project.json` 记录素材、事实、逐页提示词、真实生成来源和视觉复核，不再使用多层 manifest 契约。
- 默认使用标准模式；只有受监管品类或明确的平台上传预检才增加相应检查。
- 保留真实生成记录、商品一致性、平台无字首图、Contact Sheet 和人工验收门槛。

这是不兼容旧 manifest 的大版本。需要回退时使用 `dist/dst-skills-v6.1.0.skill`，不在 v7 生产链路中保留旧迁移代码。
