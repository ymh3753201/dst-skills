# 平台图片落点与交付

## 平台不是一种尺寸

平台名不能直接映射为一个像素。一个平台通常同时存在方形搜索主图、商品图库、3:4 主图或导购图、SKU 图、详情模块、内容封面和活动广告等多个图片落点。每个落点在项目中记录为独立 `placement`：

- `id`：项目内稳定标识；
- `name`：平台或店铺中的真实字段名称；
- `surface`：search_main / gallery / sku / detail / campaign；
- `quantity`：该落点计划交付数量；
- `aspect_ratio` 与 `selected_size`：本次真正执行的比例和像素；
- `basis`：平台硬规则、店铺主题、用户后台证据或设计建议；
- `research_ids`：支持该判断的资料。

完整平台套图默认至少两个 placement、两种实际选定尺寸。用户明确只做单一图库、单一详情模块或单张广告时，才允许一个 placement。两种尺寸不等于机械制造差异：先尊重真实平台落点，再选择能由当前图像模型执行的尺寸。

## 不同落点的任务

- 方形搜索/列表主图：优先商品识别、主体清晰和点击第一印象；是否有文字由当前平台规则决定。
- 商品图库：承担利益点、角度、细节、人物尺度和使用关系，单页仍保持一个主要问题。
- 3:4 主图或导购图：适合移动端更强的空间、人物或纵向构图，但不能简单拉长方图。
- SKU 图：颜色、规格、套餐和数量必须与真实变体一一对应。
- 详情模块：更纵向、更叙事，覆盖参数、适配、流程、清单、信任和风险说明。
- 内容封面或活动图：允许更强标题和情绪，但不能牺牲商品身份。

## 当前平台资料的使用方式

淘宝/天猫官方素材分类区分宝贝主图、长图、附加图、SKU 图、详情页图、3:4 长图和主搜 3:4 图，说明完整套图不能自动解释成一组方图：<https://developer.alibaba.com/docs/api.htm?apiId=68771>

抖店也存在方形主图、详情图以及独立 3:4 主图等不同落点；2026 年的官方通知还说明 3:4 主图字段面向全平台商家：<https://school.jinritemai.com/doudian/wap/article/aJgwEivJcR7G>

Shopify 建议同类商品媒体保持一致宽高比，但商品媒体与主题中的详情内容区仍是不同落点：<https://help.shopify.com/en/manual/shopify-admin/productivity-tools/media-editor>

Google Merchant 区分一张主图和附加图片，推荐像素也不等于站内全部详情模块规格：<https://support.google.com/merchants/answer/6324350>

平台规则会变化。指定平台完整套图展示确认前必须查询当前官方资料；需要直接上传时，还要核对当前卖家后台或店铺主题。公开资料只能证明落点、比例或最低要求时：

1. 给出可执行的 `selected_size`；
2. 把没有官方确认的像素标为“设计建议”；
3. 不把最低尺寸写成唯一尺寸；
4. 不把一个平台概括为“统一 1:1”或“统一 3:4”；
5. 每条平台结论绑定自己的研究记录，不能把两篇资料合并成一个来源。

项目必须明确记录 `platform_validation`：

- `design_recommendation`：依据当前公开资料给出可执行的比例与像素建议，不代表平台后台已验收；
- `backend_verified`：已核对用户当前卖家后台、店铺主题或真实上传回读证据。

`platform_preflight` 只能在 `backend_verified` 时使用；否则必须回退为设计建议层，不得用“符合平台标准”替代后台验证。

## 生图渠道与平台像素的衔接

平台可接受尺寸与已选图像渠道可生成尺寸是两个边界。`codex_image` 渠道执行 Image 2 尺寸合同；`arkcli_seedream_5_pro` 渠道执行 Seedream 5.0 Pro 合同；默认 `codex_image_with_arkcli_fallback` 策略必须同时通过两套合同。优先选择方形 1200×1200、3:4 的 1200×1600 等交集尺寸，但不得用一个渠道的参数规则替代另一个。平台只给最低尺寸时，不必把最低值当成唯一输出值。

若平台硬性要求的精确尺寸无法由当前图像工具生成，项目保持 `draft` 或未通过，并说明冲突；不能用提示词里的目标像素冒充真实输出，也不能用脚本裁切、缩放、补边或重新排版伪造模型直出。

## 文件与验证层级

项目至少包含：

```text
project.json
plan.md
source/
images/
review/contact-sheet.jpg
review/review.md
```

- 工程验证：合同、文件、尺寸、哈希和生成记录通过。
- 方案确认：用户可读的 `plan.md` 已完整展示并获得用户确认。
- 真实成图验证：真实参考图完成模型生成，逐图和 Contact Sheet 已复核。
- 用户验收：用户确认视觉与商品一致性。
- 平台后台验证：真实上传、后台接受并回读结果。

报告时明确当前到哪一层，不把前一层说成后一层。
