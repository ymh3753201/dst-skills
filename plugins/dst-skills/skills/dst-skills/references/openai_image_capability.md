# OpenAI 图像能力依据

截至 2026-07-15，OpenAI 官方资料支持以下工作方式：

- GPT Image 2 接受文字和图片输入并输出图片，支持高保真参考图输入与灵活尺寸：<https://developers.openai.com/api/docs/models/gpt-image-2>
- 官方把 GPT Image 2 推荐为新工作流默认模型，适合高质量生成与编辑、图内文字、写实商品、组合设计和身份敏感编辑：<https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide>
- 图像接口支持一张或多张参考图、图像编辑和多轮迭代；具体使用 Codex 内置 `imagegen` 时，以工具真实返回的模型与记录为准，不伪造底层模型名：<https://developers.openai.com/api/docs/guides/image-generation>

因此，本 Skill 让当前 Codex 多模态推理模型完成商品理解与方案设计，再让图像模型完成整页商品、场景和原生图文构图。不要把 GPT-5.x 等会变化的推理模型名称硬编码进流程，也不需要先生成底图再用本地程序排版。

## GPT Image 2 尺寸合同

官方提示词指南列出的当前约束必须在确认方案前检查：

- 两条边都必须是 **16 的倍数**；
- 最大边必须小于 **3840** 像素；
- 长边与短边比例不得超过 3:1；
- 总像素不得超过 **8,294,400**，也不得低于 **655,360**；
- 超过 2560×1440 的输出应视为实验范围，稳定性可能下降。

因此 `1080x1440`、`800x800` 等看似常见的平台尺寸不一定能直接作为 Image 2 请求尺寸。应先确认平台接受范围，再选择兼容的实际生成与交付尺寸，例如 `1200x1200` 或 `1200x1600`；如果平台硬规则与模型能力冲突，项目保持未通过并如实说明。

## 提示词应发挥的能力

- 按“场景/背景 → 商品主体 → 关键细节 → 约束”组织页面提示词，并写明最终用途。
- 多张参考图按编号和角色说明，例如“图 1 是正面身份参考，图 2 是接口细节，图 3 只参考风格”。
- 需要出现在图中的逐字文字放在引号中，要求原样呈现，同时描述字体气质、大小、颜色、位置、层级和与商品的空间关系。
- 明确要求保持商品身份、几何比例、Logo、结构、颜色和关键细节；一次修改尽量只解决一个问题，便于控制漂移。
- 电商成图提示词应像创意简报：同时写明品牌/商品定位、目标买家、创意概念、场景、构图和准确文案，而不是只堆镜头与负面词。

以上方法来自 OpenAI 官方 [GPT Image 提示词指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)。

## 能力边界与验收

官方仍提示：精确文字位置与清晰度、跨次生成一致性、品牌元素和复杂结构化布局可能失误。因此“模型原生”不等于“一次必过”。文字、商品身份、布局层级、品牌风格和视觉质量应分别验收，任何关键项失败就继续用图像模型编辑或重做。

OpenAI 的图像评测示例也把指令遵循与文字正确性设为硬门槛，把布局层级、品牌风格和视觉质量分开评分，并保留人工视觉复核：<https://developers.openai.com/cookbook/examples/multimodal/image_evals>。本 Skill 的逐图检查和 Contact Sheet 复核沿用这一原则，不用平均分掩盖错字或商品漂移。
